# learning-test — память проекта

Набор обучающих тестов (GitHub Pages). Прогресс сохраняется в localStorage и
синхронизируется с Google Drive. Сайт **публикуется из ветки `main`** (GitHub
Pages) — чтобы изменения появились на сайте, они должны попасть в `main`.

## Архитектура

- `scripts/content/<slug>.json` — исходные данные теста: массив из **50** вопросов
  `{q, options[4], correct, explain, usage}`. `correct` — индекс правильного
  варианта (0..3). `usage` = `{code, without, with, benefit}` (пример «как без
  этого / как с этим»).
- `scripts/template.html` — шаблон страницы теста. **Варианты перемешиваются в
  рантайме**: при каждой загрузке страницы (и при сбросе прогресса) `shuffle` +
  `buildShuffledQuestions` строят копию `QUESTIONS` со случайным порядком
  вариантов и пересчитанным `correct`; перемешанный порядок нигде не сохраняется.
  Поэтому в `state.answers[i]` лежит **`selectedText`** (текст выбранного
  варианта), а не индекс — индекс после следующего перемешивания указывал бы на
  другой вариант. Прогресс, записанный до этой правки, сохраняет счёт
  (`correct`), но не подсветку ранее выбранного неверного варианта.
  Проверка: `node scripts/test_shuffle.js` (без браузера).
- `scripts/build.py` — вшивает `content/*.json` в шаблон → `tests/<slug>.html`.
  **После любой правки контента запускать `python3 scripts/build.py`.**
- `index.html` — список тестов; `sims/` — интерактивные лаборатории; `sync.js` —
  общая синхронизация всех тестов с Google Drive; `config.js` — GOOGLE_CLIENT_ID.
- `progress.js` — **общая логика прогресса** для главной, страниц тестов и
  `node scripts/test_progress.js`: статус, ошибки, какая копия
  свежее при синхронизации, курс TSI по названию. Считать это где-то ещё — значит
  однажды получить группу на главной, которая не совпадает с подписью в тесте.
- Главная: карточка «Продолжить» (последний открытый тест, если он не пройден,
  иначе самый свежий из начатых; ключ `ltindex_last`), группы «В процессе»,
  «Работа над ошибками», «Не начаты», «Выполнены», «Лаборатории»
  (`SIMS` в index.html — при новой лаборатории дописать туда). Курс TSI из 2+
  тестов в группе — одна сворачиваемая строка. Раскрытие запоминается в
  `ltindex_open`. Свои ключи главная держит **вне** `learntest_…`: `sync.js`
  отправляет в Drive каждый ключ с этим префиксом как прогресс теста.
- Поля состояния теста сверх `current`/`answers` (все необязательные, старый
  прогресс без них работает): `updatedAt` (по нему слияние решает, что свежее),
  `fixed` (ошибки, исправленные в «Работе над ошибками» — **счёт теста они не
  меняют**). Пройден = `current>=50` **или** все 50 отвечены: «Пересмотреть
  ответы» сбрасывает `current`. Интервальное повторение («Пора повторить») было
  и убрано 17.10.2026 по просьбе Игоря; `doneAt`/`review` в старом прогрессе от
  него, их никто не читает — не возвращать без запроса.
- Режим страницы теста: `tests/<slug>.html?mode=mistakes`. Обычный проход
  (`answers`) он не трогает.
- Синхронизация: главная при открытии сама сливает прогресс (`LTSync.syncAll`,
  свежее побеждает), страница теста тихо шлёт свой тест после ответа
  (`uploadOne`) — **только пока жив Google-токен** (~час после входа). Без токена
  автоматика молчит: окно входа без касания браузер блокирует, поэтому строка под
  заголовком главной становится одним касанием. Сбой списка файлов Drive — ошибка,
  а не «там пусто»: иначе слияние залило бы всё заново дубликатами.
- Формат JSON контента — **компактный**: массив, по одному вопросу на строку,
  разделители без пробелов. Скрипты правок это сохраняют.

## Правила создания тестов (ОБЯЗАТЕЛЬНО)

Цель — чтобы правильный ответ нельзя было угадать по **форме**, а только по
знанию. Все правила проверяются `python3 scripts/check_quality.py` (код возврата
≠ 0 при нарушении). Запускать этот чек перед коммитом любого теста.

1. **Ровно 50 вопросов** в тесте, у каждого **ровно 4 варианта** — непустых и
   различных; `correct` в диапазоне 0..3.

2. **Позиция правильного ответа — случайная.** Основную защиту даёт
   **перемешивание в рантайме** (см. `scripts/template.html`): позиция меняется
   на каждой загрузке, поэтому её нельзя запомнить со второй попытки, и порядок
   в `content/*.json` для проходящего тест значения не имеет. Проверка в
   `check_quality.py` (каждая позиция ≥ ~5 раз из 50) остаётся как **страховка**
   на случай, если рантайм-перемешивание однажды уберут: правильный не должен
   систематически стоять на одной позиции и в самих данных (частая ошибка —
   почти всегда индекс 0 или 1). Инструмент: `python3 scripts/shuffle_options.py`
   перемешивает варианты и пересчитывает `correct`. Перемешивать контент заново
   ради «нельзя угадать позицию» больше не нужно — это уже решено в рантайме.

3. **Правильный ответ НЕ должен быть самым длинным.** Нельзя, чтобы правильный
   опознавался по объёму текста. Требования: длины всех 4 вариантов сопоставимы;
   доля «правильный строго самый длинный» ≤ ~35% (в идеале ~25%); средняя длина
   правильного ≈ средней длине неправильных. Как достигать: правильный подрезать,
   где многословно; неправильные дополнять **правдоподобными, но фактически
   неверными** деталями до похожей длины (не превращать дистрактор в правду и не
   делать его перефразом правильного).

4. **В правильном ответе не должно быть выдающих круглых скобок `( )`.** Скобки
   часто ставят только в правильном (пояснения, формулы, аббревиатуры) — и это
   выдаёт ответ. Правило: **не должно быть вопросов, где скобка есть только у
   правильного варианта.** Способы: убрать скобку из правильного (перефразировать)
   ИЛИ добавить естественную скобку в один из **неправильных** вариантов (оставив
   его однозначно неверным). Правильный вариант при этом по смыслу не менять.

5. **Содержание.** Правильный остаётся фактически верным; неправильные —
   однозначно неверными и не перефразом правильного. `usage`, `q`, `explain` при
   косметических правках вариантов не трогать.

6. **Практический блок — многошаговый.** Блок 5 «Практика и расчёты» (вопросы
   40..49, `blockOf(idx)==4`) — это 10 ПРАКТИЧЕСКИХ задач, каждая решается НЕ в
   одно действие, а за цепочку из **2–3 шагов** (максимум 5): дано → применить
   правило/формулу → посчитать/рассудить → выбрать ответ. Для технических тем —
   числовые расчёты; для концептуальных/«мягких» — прикладной кейс с разбором
   ситуации. Дистракторы = типичные ошибки в шагах. Скрипт `apply_practical.py`
   заменяет блок 40..49 из `scripts/practical/<slug>.json`, не трогая 0..39.
   Правило применяется к тестам, которые пользователь ещё НЕ прошёл (прогресс
   виден в Google Drive: `learntest_<slug>.json`, `current==50` = пройден).

## Картинки к вопросам

У вопроса может быть картинка: поле `img` = `{src, alt, credit?}` в
`content/<slug>.json`, файл `img/<slug>/NN.svg` (NN = номер вопроса 01..50;
допустимы также gif/png/jpg/webp). Подписи лежат в `img/<slug>/meta.json`
(`{"01": {"alt": "...", "credit": "..."}}`); поле `img` в контент вписывает
`python scripts/images.py attach <slug>` — руками его не править.
Шаблон показывает картинку под текстом вопроса, касание открывает её целиком.

1. **Картинка не выдаёт ответ.** Её видно ДО ответа. Она показывает, о чём
   вопрос — объекты, постановку, данные, геометрию, — но не результат, не
   формулировку правильного варианта и не его отличительный признак. В задаче на
   расчёт рисуются данные, а не ответ. Проверка: глядя только на картинку,
   нельзя предпочесть правильный вариант дистракторам.
2. **Верность.** Углы, длины, графики соответствуют числам из вопроса;
   координаты считаются, а не ставятся на глаз.
3. **Формат SVG.** `viewBox="0 0 480 300"` (высота 240–360), своя белая
   подложка (у страницы две темы), шрифт от 16 (на телефоне картинка ~340 px),
   без `<script>`, `foreignObject` и внешних ссылок — работает офлайн, до 60 КБ.
   Анимация (SMIL или CSS внутри SVG) — там, где речь о движении или процессе;
   первый кадр тоже осмысленный.
4. **Чужие картинки** — только со свободной лицензией и с `credit`
   (автор, лицензия, адрес); файл хранится в репозитории, а не по ссылке.
5. Проверка: `python scripts/images.py check` (файлы, размеры, офлайновость,
   правильный вариант целиком на картинке) и **глазами** —
   `python scripts/images.py sheet <slug>` снимает листы по 10 картинок в
   ширину телефона (через headless Chrome, `scripts/sheet_shot.js`), а
   `python scripts/images.py frames <slug>` — кадры каждой анимации на 0, ¼, ½,
   ¾ цикла. `check` ловит и формат: viewBox, белую подложку первым элементом,
   шрифт меньше 16, линии тоньше 1.5. `check_quality.py` дополнительно ловит
   `img`, чей файл пропал.
6. Если точный чертёж сам выдаёт ответ (поза, по которой читается положение
   инструмента; переходная, по которой меряется перерегулирование), рисуется
   схема обозначений с заведомо другими значениями и подписью «значения
   условные», а настоящие числа — в рамке «дано».

## Формулы

Формулы в `q`, `options`, `explain` и в `usage` без кода пишутся в LaTeX:
`\( ... \)` — в строке, `\[ ... \]` — отдельной строкой (в JSON обратный
слэш удвоен). Рендерит KaTeX из `vendor/katex/` (без CDN); код в ``` ``` и
`usage` с `code: true` не трогается. **`$` разделителем не служит** — в тестах
по ассемблеру и shell он значит константу и переменную. Десятичная запятая
внутри формулы — `0{,}5`, иначе KaTeX ставит после запятой пробел.

1. **Оформление не выдаёт ответ.** Если правильный вариант набран формулой,
   дистракторы с такими же выражениями набираются так же (`check_quality.py`
   ловит вопрос, где LaTeX только у правильного). Длину и скобки правил 3–4
   `check_quality.py` считает по видимому тексту, а не по исходнику LaTeX.
2. `node scripts/check_math.js [slug]` разбирает каждую формулу KaTeX'ом; на
   странице ошибка не падает, а показывается сырым исходником — глазами её
   легко пропустить. `check_quality.py` проверяет, что разделители закрыты.

## Рабочий процесс правок контента

1. Правки в `scripts/content/*.json` (или через вспомогательные скрипты —
   `shuffle_options.py`, `apply_balanced.py`, `apply_parenfix.py`, `merge_usage.py`;
   они пишут компактный формат и содержат ассерты целостности).
2. `python3 scripts/check_quality.py` и `node scripts/check_math.js` — все тесты
   должны пройти.
3. `python3 scripts/build.py` — пересобрать HTML.
3b. `node scripts/test_progress.js` — после правок `progress.js`, `sync.js`,
   главной или режимов теста: логика прогресса и слияние с Drive на заглушке.
3a. `node scripts/test_shuffle.js` — после правок `template.html`: проверяет, что
   перемешивание есть во всех собранных `tests/*.html`, что оно вызвано, и что
   `correct` едет вместе с вариантами (иначе тест молча считал бы верным не тот
   вариант).
4. Проверить в браузере (Playwright есть в окружении: модуль в
   `/opt/node22/lib/node_modules/playwright`, Chromium предустановлен).
5. Коммит в рабочую ветку; чтобы попало на сайт — слить в `main` (Pages
   пересоберётся автоматически).

## Полезное

- Разработка идёт в отдельной ветке; `main` — то, что задеплоено. Разрыв «на
  сайте старая версия» обычно значит, что последние коммиты не влиты в `main`.
- Проверка деплоя: workflow `pages build and deployment` (все запуски — с `main`).
- Модель раздачи GitHub Pages кэширует HTML; для проверки свежей версии —
  жёсткое обновление (Ctrl/Cmd+Shift+R) или приватное окно.
